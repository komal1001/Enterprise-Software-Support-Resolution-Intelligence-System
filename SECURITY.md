# Security Policy

## Supported Versions

The project is currently maintained as a portfolio/demo project. Security updates
are handled on the main branch and may be backported only when necessary.

## Reporting a Vulnerability

Please do not report security vulnerabilities through public GitHub issues,
discussions, or pull requests.

Instead, report privately using one of the following channels:

- Open a private security advisory on GitHub, if available for this repository
- Contact the maintainer directly via a private email or other secure channel listed in the repository metadata

Please include:

- a clear description of the vulnerability
- steps to reproduce it
- the affected component or file
- the impact and likely severity
- any suggested mitigation or fix

## What to Expect

We will review your report as quickly as possible and aim to acknowledge it
within a reasonable timeframe. If the issue is confirmed, we will work to
prepare a fix and coordinate disclosure responsibly.

## Responsible Disclosure

Please practice responsible disclosure by not exposing the vulnerability publicly
until a fix has been released or a reasonable remediation plan has been agreed.

## Security Best Practices for Contributors

- Never commit real credentials, API keys, or secrets
- Use environment variables and sample configuration files only
- Review dependencies and update them regularly
- Report suspicious behavior privately rather than in public forums
